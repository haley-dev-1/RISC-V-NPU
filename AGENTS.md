## 4. Head Start on Core NPU Modules (MANDATORY DESIGN GUIDANCE)

The agent MUST design the following modules with the listed minimum features and dependencies.  
These are architectural requirements, not suggestions.

### 4.1 Module Breakdown

| Module Name        | Must-Have Features                                           | Depends On          |
|--------------------|---------------------------------------------------------------|---------------------|
| mac32              | 32-bit signed MAC, overflow handling, saturation support     | None                |
| systolic_array     | Wavefront propagation, local weight storage                  | mac32               |
| sram_buffer        | Dual-port access (DMA write, Array read)                     | Array size          |
| dual_dma           | Strided 2D access, burst support, SRC/DST channels           | System bus spec     |
| npu_fsm            | Idle -> Load -> Compute -> Store state machine               | DMA + Array         |
| tinyQV_core        | Quantized compute pipeline, MAC scheduling                   | Array + SRAM        |
| tinyQV_top         | System integration wrapper                                   | FSM + DMA + Core    |

---

### 4.2 32-bit MAC (mac32.v)

Requirements:
- Signed multiplication
- 32-bit accumulator
- Overflow detection
- Optional saturation mode (parameterized)
- Single-cycle or multi-cycle (must document choice)

The MAC must be standalone and independently testable.

---

### 4.3 Systolic Array (systolic_array.v)

Requirements:
- Choose array size: 4x4 or 8x8
- Justify choice in prompt log (area vs performance tradeoff)
- Wavefront data propagation
- Local weight registers per PE
- Parameterized data width

Dependencies:
- Uses mac32 as processing element

---

### 4.4 SRAM Buffers (sram_buffer.v)

Requirements:
- Dual-port access:
  - Write port: DMA
  - Read port: systolic array
- Configurable depth
- Separate input and output buffers (or clearly multiplexed)
- No write-read conflicts allowed

Dependencies:
- Sized to match systolic array dimensions

---

### 4.5 Dual-Channel DMA (dual_dma.v)

Requirements:
- Independent SRC (read) and DST (write) channels
- Descriptor-driven operation
- Strided 2D addressing
- Burst transfers
- Abort and error handling
- Bounds checking

Dependencies:
- System bus interface provided by peripheral.v
- Controlled by npu_if_bridge

---

### 4.6 NPU FSM (npu_fsm.v)

Required States:
1. IDLE
2. LOAD   (DMA -> SRAM)
3. COMPUTE (Array active)
4. STORE  (SRAM -> DMA)
5. DONE / ERROR

Requirements:
- Deterministic transitions
- Timeout/watchdog awareness
- Explicit stall handling

Dependencies:
- dual_dma
- systolic_array
- sram_buffer

## 5. Focus Area A: tinyQV MMIO Integration

### Purpose
Expose tinyQV control and DMA descriptors via MMIO so the CPU can:
- configure operations
- launch tinyQV
- monitor status
- receive interrupts

### MMIO Register Map (32-bit)

BASE + 0x00 CMD
[0] START
[1] ABORT
[2] IRQ_EN
[3:7] OPCODE
[8:15] QPARAM

BASE + 0x04 STATUS
[0] BUSY
[1] DONE
[2] ERROR
[3] DMA_BUSY

BASE + 0x08 SRC_DESC_PTR
BASE + 0x0C DST_DESC_PTR
BASE + 0x10 CONTROL
BASE + 0x14 PERF_CNT_LO
BASE + 0x18 PERF_CNT_HI
BASE + 0x1C WATCHDOG

## 6. Focus Area B: Dual-Channel DMA

### Required DMA Tests (dma_unit_tb.v)

1. Single descriptor copy
2. Multi-descriptor chain
3. Abort mid-transfer
4. Backpressure / stall injection
5. Invalid descriptor detection

All tests must self-check and print PASS or FAIL.

---

## 7. Focus Area C: End-to-End Testbench

### e2e_npu_tb.v Must Demonstrate

1. CPU writes MMIO registers
2. Descriptor lists written to memory
3. Dual DMA transfers data
4. SRAM buffers filled
5. Systolic array compute
6. DMA writes results back
7. CPU detects DONE or IRQ
8. Output memory matches software reference
